# 📏 단위테스트 공통 수행 규칙 (Unit Test Rules)

단위테스트 수행 시 일관된 품질과 리포팅을 보장하기 위해 아래 규칙을 반드시 준수합니다.

---

## 1. 판정 및 기록 기준

- **✅ Pass**: 테스트 케이스(TC)의 예상 결과와 실제 결과가 완전히 일치하는 경우.
- **❌ Fail**: 예상 결과와 다르거나 런타임 오류가 발생하여 기능 수행이 불가능한 경우. (결함 설명 및 재현 로그 필수 첨부)
- **➖ N/A (Not Applicable)**: 현재 테스트 환경이나 조건에서 수행할 수 없는 케이스인 경우. (사유 명시 필요)

## 2. 결함 발견 시 대응 요령

결함이 발견되어 `❌ Fail` 판정이 난 경우, 아래 프로세스를 따릅니다.
1. **결함 상세 분석**: 발견된 결함이 코드 레벨에서 어떤 문제(오타, 로직 미비 등)인지 파악.
2. **해결 방안 제시**: (에이전트) 수정할 코드 스니펫 제안.
3. **긴급 수정 및 재테스트**: 수정 사항을 즉시 반영하고 다시 테스트하여 Pass 여부를 리포트에 업데이트.

## 3. 리포팅 규격 및 산출물 관리

- **파일 포맷**: 마크다운(`.md`) 파일로 작성하되, 필요 시 엑셀(`DEV_TS_0003`)로 변환 가능한 구조 유지.
- **파일명 규칙**: `DEV_TS_0003_단위테스트_결과서_[파일명/기능명]_[날짜].md`
- **저장 위치**: `unit_test/reports/` 폴더에 형상 관리.
- **증빙 첨부**: API JSON 페이로드, 에러 로그, UI 캡처본(Canvas/Image)을 `### 증빙` 섹션에 포함.

## 4. UI/UX 및 반응형 점검 필수 사항

모든 UI 컴포넌트 단위테스트에는 다음 상황에 대한 검증을 포함해야 합니다.
1. **브라우저 창 리사이징**: 1920px(데스크톱)에서 375px(모바일)까지 부드럽게 조정되는가?
2. **입력값 유효성**: 빈값, 특수문자, 과도한 길이의 텍스트 입력 시 레이아웃이 유지되는가?
3. **색상 및 폰트**: 공식 디자인 가이드(디자인 시스템)에서 정의된 토큰과 일치하는가?
