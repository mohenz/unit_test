# 🔄 단위테스트 수행 표준 워크플로우 (Unit Test Workflow)

이 문서는 워크스페이스 내 프로젝트의 단위테스트를 수행하기 위한 표준 절차를 정의합니다. 모든 에이전트와 작업자는 이 프로세스를 준수하여 일관된 품질의 테스트 결과서를 산출해야 합니다.

---

## 1. 단계별 수행 절차

### 1단계: 테스트 대상 분석 (Analysis) 🔍
- **목표**: 테스트할 기능의 요구사항과 소스 코드를 이해합니다.
- **활동**:
  - 관련 HTML, JS, CSS 파일의 구조 분석
  - 데이터 흐름(API 연동, State 관리) 파악
  - UI/UX 설계 요건 확인 (반응형, 컬러 가이드 등)

### 2단계: 테스트 케이스 도출 (Test Case Planning) 📋
- **목표**: 검증이 필요한 시나리오를 구체화합니다.
- **활동**:
  - **정상 케이스**: 기본 기능이 의도대로 동작하는가?
  - **예외/경계 케이스**: 잘못된 입력, 네트워크 오류 등에 적절히 대응하는가?
  - **UI/UX 케이스**: 디자인 가이드를 준수하며 반응형 레이아웃이 깨지지 않는가?
- **산출물**: 테스트 케이스 목록 (결과서 초안)

### 3단계: 테스트 수행 및 증빙 채득 (Execution & Evidence) 🛠️
- **목표**: 실제 환경(또는 브라우저 시뮬레이션)에서 기능을 검증하고 근거를 수집합니다.
- **활동**:
  - 각 케이스별 실행 결과 확인 (Pass/Fail 판정)
  - 결함 발견 시 상세 현상 기록 및 재현 경로 파악
  - 증빙 자료 수집:
    - 화면 캡처: 주요 UI 상태, 에러 메시지 노출 화면
    - 데이터 로그: API Request/Response Payload (JSON), 콘솔 로그

### 4단계: 결과서 작성 및 리포팅 (Reporting) 📝
- **목표**: 표준 규격에 맞춘 결과 산출물을 생성합니다.
- **활동**:
  - `DEV_TS_0003` 템플릿(Markdown) 작성
  - 공통 체크리스트 항목 판정 기록
  - 증빙 자료(이미지, 코드 블록) 첨부
- **결과물**: `reports/DEV_TS_0003_단위테스트_결과서_[기능명].md`

---

## 2. 결함 발견 시 대응 프로세스

단위테스트 수행 중 결함(Bug)이 발견되면 다음과 같이 조치합니다.

1. **결함 식별**: 실제 결과가 예상 결과와 다른 경우 Fail 판정.
2. **원인 분석**: 코드 레벨에서의 원인(Selector 오타, 로직 오류 등) 파악.
3. **수정 제안**: (에이전트 수행 시) 발견된 결함에 대한 수정 코드 제안 및 필요시 직접 수정.
4. **재테스트**: 수정 사항 반영 후 해당 케이스 다시 수행 및 Pass 확인.

## 3. 도구 및 스킬 활용

- **AI 스킬**: `skill_generate_unit_test.md`에 정의된 프롬프트를 활용하여 리포트 자동 생성.
- **브라우저 도구**: Chrome DevTools를 활용해 DOM 구조 및 네트워크 트래픽 분석.
- **Git/File**: 결과서 파일을 `unit_test/` 폴더에 형상 관리.
